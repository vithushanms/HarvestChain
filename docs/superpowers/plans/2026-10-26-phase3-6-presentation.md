# HarvestChain Phases 3–6 — Presentation, UI, Loader, Polish

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Turn the finished simulation (phase 2) into the shipped game: a lit isometric 3D pixel scene rendered by the Wasm itself, a touch/mouse UI, the 3-file loader, replays/share codes, onboarding and polish (spec §13–§15, §14.6 steps 3–6).

**Architecture:** The module owns rendering end-to-end: an integer-only software rasteriser (flat-shaded polygons with per-face light ramps, painter's-algorithm depth order) draws an isometric farm into an RGBA framebuffer at the logical resolution; 2D UI chrome and bitmap fonts draw over it. `index.html` is dumb glue (spec §14.2). Layouts are data. Everything is tested headlessly by hashing the framebuffer and probing pixels, then smoke-tested in a real browser.

**Tech Stack:** As before (WAT, wabt, Binaryen, `node:test`) plus Playwright (chromium) for browser smoke tests only (devDependency).

**Spec:** `requirement-spec.md` §13–§15 and §3. Read `CLAUDE.md`, `README.md`, and plans for phases 1–2.

## Global Constraints

- All earlier constraints hold: integer-only, MVP + bulk-memory + sign-ext + mutable-globals, all randomness via `$rng_next`, numbers in `03_balance.wat`, fragments concatenated by filename.
- Zero asset files: no images, fonts or audio; every pixel comes from data segments or code.
- Min touch target 44×44 CSS px (enforced in layout code); no horizontal scroll; usable at 360×640 and 1440×900; keyboard map from spec §13 (E, 1–5, H, Esc, arrows, Enter, `` ` ``, R).
- Rendering must be deterministic (same state + size → same framebuffer bytes) and must not call `$rng_next` (use a separate render-only hash noise function of tile index/day) so replays are unaffected.
- Every number the stats overlay shows is measured live, never hard-coded.

## Decisions (spec silent or conflicting)

1. **"3D" = software isometric 3D.** 2:1 dimetric projection of a world with integer coordinates (tile = 16×16 world units, height in units). Primitives: `box`, `prism` (gabled roof), `cone`/`dome` (via stacked shaded discs), `cyl`. Light from the upper-left: top face ramp step 3 (brightest), left face 2, right face 1; ground shadow = darkened diamond offset right-down. Depth order = painter's algorithm by (row+col) then height, which is exact for a grid of non-overlapping tiles.
2. **Palette:** the spec's 16-colour/64-byte table becomes **16 hues × 4 light ramp steps = 64 entries × RGBA** (256 B) so shaded faces stay inside a fixed palette. Contrast ≥ 4.5:1 is checked for UI text against its panel colours by a test.
3. **Logical resolution:** `logical = floor(css_size * dpr_capped_2 / pixelScale)` with `pixelScale = max(1, round(min(w,h)/360))`, clamped to ≤ 720×1280. Framebuffer lives at `$R_FB`; memory is grown (`memory.grow`) to fit `R_FB + w*h*4` on `resize`. *This resolves the phase 1 open question: the spec's "≤ 2.6 MB" was wrong; the max is 3.69 MB.*
4. **Size budget:** keep the spec's 20 KB gz as the target. If the renderer + UI + QR cannot fit, the implementer may raise `wasmGz` in `tools/build.mjs` to at most **32 KB** and `wasmRaw` to **80 KB**, but must first try: sharing code between sprites, 4 bpp packing, string-table trimming. Any raise is a ledger ruling and a README note.
5. **Fonts:** 5×7 body (uppercase, digits, `.,:;!?-+/%$★▲▼·()'` etc.) and 3×5 badge font, packed 1 bit/pixel.
6. **Render noise:** `noise(tile, day)` = integer hash used for dither, field two-tone, cloud drift; never the sim RNG.
7. **Weather particles:** a fixed pool of 256 particles in scratch memory advanced by `frame(now_ms)`; reduced-motion disables them and panel slides.
8. **Frame loop:** `frame(now)` returns 1 if anything is animating or dirty. Loader keeps calling rAF only while it returns 1 (idle = 0 CPU).
9. **Input contract:** `pointer(x, y, type)` type 0 down, 1 move, 2 up in CSS px; `key(code, down)` with `KeyboardEvent.code` mapped to a small int table in the loader.
10. **Share code:** base64url(`seed u32 · version u16 · deflate-free RLE input log`). The spec says "deflated"; a hand-written inflate is too large for the budget, so the log uses a compact varint + RLE encoding and a measured size is shown. *Ruling: no DEFLATE; target ≤ 1 KB for a 240-day run.*
11. **QR:** in-canvas QR (byte mode, version up to 10, ECC L) generated by a small hand-written encoder in Wasm; falls back to showing only the text code if the payload exceeds capacity.
12. **Playwright** is dev-only; browsers installed with `npx playwright install chromium`. If it cannot be installed, the smoke task falls back to a Node + `jsdom`-free harness that drives `frame()`/`pointer()` directly and records the limitation in the ledger.

## Review Focus

- **Phone portrait at 360×640 with large-text on:** nothing overlaps, every button ≥ 44 CSS px, End Day always reachable. → layout tests assert rect sizes and non-overlap for all three layouts × large-text.
- **Resize / rotate mid-game and pointer events during a panel slide:** no crash, hit regions rebuilt, selection kept or cleanly cleared. → Task 5.
- **Reduced motion and DPR 1/2/3:** crisp integer scaling, particles off. → Task 3 / 6.
- **Corrupt or old `localStorage` save, or a bad `#hash`:** falls back to New Game / ignores the hash, never a blank screen. → Task 6 / 7.
- **Rendering must not mutate game state or the RNG:** a render-only frame must leave state bytes identical. → Task 1 test, re-asserted in Task 5.

## Tasks

### Task 1: Framebuffer, palette, draw primitives, fonts (phase 3a)

**Interfaces — Produces:** `resize(w_css, h_css, dpr_x100) → void` (computes logical size per Decision 3, grows memory), `fb_ptr()→i32`, `fb_w()→i32`, `fb_h()→i32`, `$px(x,y,c)`, `$fill(c)`, `$rect(x,y,w,h,c)`, `$rrect(x,y,w,h,r,c)`, `$hline/$vline`, `$line`, `$text(x,y,str_ptr,c,font)`, `$text_w`, `$noise(a,b)`, `$dither(x,y,level)`; test export `t_draw_demo(kind)`.

- [ ] Tests (`tests/render/draw.test.mjs`): `resize` computes expected logical sizes for (360,640,2), (1440,900,1), (390,844,3); memory covers the framebuffer; `rect` fills exactly w×h pixels and clips at edges (no write outside buffer — check a guard canary byte after the buffer); `text` of "HARVEST" has expected pixel count and width = `chars*6-1`; palette entry spot-checks (entry 0 transparent-free, ramps monotonic in luminance within each hue); **render does not touch state or RNG** (state bytes + rng word identical before/after a full draw); framebuffer hash of the demo scene is stable run-to-run.
- [ ] Implement, commit `feat(render): framebuffer, palette, primitives and fonts`.

### Task 2: Isometric 3D rasteriser (phase 3b)

**Interfaces — Consumes:** Task 1 primitives. **Produces:** `$iso_origin(ox, oy)`, `$iso_tile_w/h` (constants from layout), `$iso_proj(wx, wy, wz) → (sx, sy)`, `$poly4(x0,y0,…,x3,y3,c)` (scanline convex quad fill, integer edge walking), `$box(wx,wy,wz,w,d,h,hue)`, `$prism(wx,wy,wz,w,d,h,roof_h,hue)`, `$disc_shaded(cx,cy,r,hue)`, `$cyl(wx,wy,wz,r,h,hue)`, `$shadow(wx,wy,w,d)`.

- [ ] Tests: projection of known world points; `poly4` fills a known diamond to the exact pixel count; box top face uses ramp step 3, left 2, right 1 (pixel probes); painter's order — a taller box in front hides one behind (probe overlapped pixel); sphere shading brightest at upper-left; shapes are clipped to the framebuffer without out-of-bounds writes (canary).
- [ ] Implement, commit `feat(render): software isometric 3D rasteriser`.

### Task 3: Scene art (phase 3c)

**Produces:** `$scene_draw()` renders the whole farm for the current state at the current framebuffer size: sky gradient with season tint and sun/clouds (noise-drifted), terrain tiles with seed-derived two-tone dither, per-crop 3-stage models (wheat stalks, corn stalks, tomato vines with red fruit, apple tree with trunk + dome canopy + fruit when ripe, grape trellis), 10 building models (mill with sails, cannery tank, press, bakery chimney, cellar half-buried, warehouse, cold store, greenhouse glass box, well, garage), grid-expansion border, truck models on a route strip, weather particles (rain, storm flashes, frost sparkle, heat shimmer, drought dust), ripe sparkle, "storage full" badge. `$tile_screen_rect(idx)` for hit-testing.

- [ ] Tests (`tests/render/scene.test.mjs`): golden framebuffer hashes (SHA-256) for ≥ 8 canned scenes at 360×640 and 1280×800 — day-1 farm, mid-season mixed, winter, storm, all buildings, full 8×8 grid, truck en route, night/frost; scene draw leaves state/RNG untouched; every crop has 3 visually distinct stage hashes; reduced-motion flag removes particles (hash equals the particle-free scene); `$tile_screen_rect` rects are inside the framebuffer and non-overlapping for the active grid.
- [ ] Implement; write a dev script `tools/dump-ppm.mjs` that renders a canned scene to `build/scene-*.ppm` → PNG (pure Node zlib) so a human can eyeball it. Commit `feat(render): lit isometric farm scene`.
- [ ] **Visual check (required):** run the dump script, open the PNGs with the Read tool, and iterate on the art until it reads as a coherent, attractive 3D farm; note what was adjusted in the report.

### Task 6: Loader, service worker, PWA, browser smoke (phase 4c)
